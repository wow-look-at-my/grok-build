# Thinking-replay notes

- One policy decides what a replayed `Reasoning` item does on every backend: `conversation/thinking_replay.rs` (`ThinkingReplayPlan::disposition`). A reasoning item carries words (`summary`/`content`) and a model-bound blob (`encrypted_content`: a Messages signature or a Responses encrypted body). The blob is verified against the model that minted it. Nobody verifies the words.
- The origin is the `model_id` of the `Assistant` item behind the reasoning. An alias, the dated snapshot it answers as, and a gateway's routing prefix are one model (`same_model`). Same model, or an origin nobody recorded: the item goes out as is.
- Another model: a blob with words goes out as text. A blob alone is dropped. Words alone go out as is, unless the target signs. Then they go out as text too. A model switch never drops words. Whether the target signs is read off the conversation (`target_signs_thinking`). The Messages builder adds a Claude id as knowledge of its own.
- The text form depends on the backend. Responses and Ollama send a `<thinking>` assistant message (`thinking_as_text`). The Messages builder sends a client note (`thinking_as_note`) in the user-role message that follows the turn. After a tool call that is the tool-result message, behind the results.
- The Messages builder never writes thinking into assistant text. That text shows reasoning as response text. Anthropic answers such a request with a content-filter refusal that names reverse engineering, and it bills the request. A switch between Opus and Fable produced that text before the note form.
- Each model gets its own blocks typed and the other models' thinking as notes. That body is the same on every request to one model, so the provider's check that binds a block to its conversation still passes. A typed block of another model beside a note breaks that check.
- `build_messages_request`, `build_responses_input` and the Chat Completions conversion all read the plan. Chat Completions has no blob and `reasoning_content` is unverified text. So only `Scrubbed` changes that body.
- Chat Completions sends the replayed text under `reasoning_content` and under `reasoning`. Ollama (local and ollama.com) reads only `reasoning` and ignores the other key, so a turn sent with only `reasoning_content` reaches the model with no thinking. An xAI host gets only `reasoning_content` (`ChatMessageProfile::accepts_reasoning`). A strict schema that names `reasoning` as unsupported loses that key alone.
- The static answer is a guess where the origin is missing or a same-model check is incorrect. So every path also has a fallback ladder on `ConversationRequest::thinking_replay`: `Native`, then `TextOnly`, then `Scrubbed`. The sampler steps it down on a thinking-signature or `encrypted_content` 400 (`RetryDecision::RetryWithReasoningStrip`, `degrade_thinking_replay`). Compaction calls the client directly and walks the same ladder in `run_compact_inner` over its items (`apply_thinking_replay`, `names_replayed_thinking`). A spent ladder reaches the session. Its flatten-and-resubmit covers the rest.
- Compaction never strips thinking from the verbatim input. The summarizer reads it. On Messages the compaction request goes out at `TextOnly` (`generate_session_compact`), so every summary rides as a client note and no block does. The summarizer runs under its own prompt, and no block verifies there. On the other backends the plan above decides per item.
- The lossy input keeps the thinking items on Messages only (`lossy_summary_input`). The other backends still lose them there. The text mutation invalidates a blob, and no text form is proven safe for them.
- `features.compact_on_model_switch` is off by default. `/settings` shows it under Agent as "Compact on model switch". A change applies to running sessions: the config watcher sends `ReloadCompactionFeatures`, which sets the live agent's policy and the rebuild spec's. `features.two_pass_compaction` reloads the same way. With it on, the first turn after any model change compacts (`maybe_compact_on_model_switch`), whatever the context use. A history with no model output since the last compaction is left alone. Without the setting a switch compacts only into a smaller window that is over the threshold, or across model families.
- `truncate_trailing_incomplete_tool_call` drops the reasoning ahead of the tool call it drops. A reasoning item with no assistant behind it has no origin. No origin reads as "replay it".
- A conversation that ends mid-tool-loop on a turn whose thinking the plan leaves behind goes out with thinking off fully (`open_tool_loop_lost_its_thinking`). A provider validates the thinking of the tool-calling turn it continus. A config-less thinking block is rejected in turn. Reasoning effort is untouched and the next turn pairs normally.
