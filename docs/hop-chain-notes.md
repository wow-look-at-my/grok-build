# Hop-chain notes

`models.providers.<id>.hops` lists the proxies between this client and a provider, client side first. The user guide's "Proxy Hops" section is the field reference.

- The chain is applied where a client is built, not in the catalog. `Config::new_from_toml_cfg` resolves every provider's chain (`agent/model_route.rs`) and hands the table to `xai_grok_sampler::provider_route`. `SamplingClient::new` looks its `base_url` up there and sends to the first hop that is on. So a catalog entry keeps the provider's own URL and model id. A session finds its model by those. A toggle does not move it.
- A model that sets a `base_url` of its own matches no provider URL in the table. It is off the chain.
- Every `SamplingClient` built for the provider's URL takes the chain: turns, side calls, web search and embeddings. The model listing (`remote/model_source`) builds no `SamplingClient`. It goes to the provider's own URL.
- The gateway `model_prefix` goes on in the backend `apply_*defaults` functions, one time per request. It is not idempotent on purpose: `openrouter/auto` through a gateway that prefixes `openrouter/` is `openrouter/openrouter/auto`.
- A chain that cannot resolve is published as an `Err` target. `SamplingClient::new` refuses with the reason. A hop `env_key` that names no set variable is such an error, because the provider's key must never go to that hop.
- The config watcher calls `publish_from_raw` when `model_providers` changes (`config/reloader.rs`). The table is process-wide, so no session is told and the next request takes the new path. `ModelsChanged` does not fire for a hop toggle, so no provider is listed again.
- `set_hop_enabled` (`util/config/settings_writes.rs`) writes `enabled` on one hop of the USER config. A hop that file does not hold, or one that is not optional, is an error.
- Every streaming request reports a `RequestTransport` on `ResponseModelMetadata.transport`: the body encoding, both sizes, the wait for the headers and any `Server-Timing` metrics. `SentBody::of` reads the encoding off the request as sent, so a resend after a lost delta base reports the full frame. The shell forwards it as the transient `SessionUpdate::RequestTransport`.
- The upstream's name comes from the response body: OpenRouter's top-level `provider`, then the `provider` in Bifrost's `extra_fields.raw_response`, then Bifrost's own `extra_fields.provider` (`upstream_provider_of`). The Chat Completions and Messages transforms emit `SamplingEvent::UpstreamProvider`. Responses has no such field.
- The pager draws the reported name unless it only repeats a link of the chain. Then the model id's vendor segment stands in (`provider_brand::serving_provider`).
- `IconLabel` (`views/icon_label.rs`) is the control that draws a mark and a name. The label is cells. The mark is a Kitty placement over blank cells, sent after the frame by `IconLayer`, with image ids from `0x7000_0000` up. A terminal with no graphics gets the label alone. The gate is `scrollback_inline_overlay_active`, the one inline media uses.
- The marks in `assets/provider-icons/` are simple-icons paths (CC0-1.0). `rsvg-convert` drew each as a PNG and ImageMagick `-colorize` tinted it.
- The route dialog (`views/hops_dialog.rs`, `app/dispatch/hops.rs`) reads the chain and probes each link through effects, because dispatch touches no disk and no network. A probe is the faster of two GETs, and any HTTP answer counts.
